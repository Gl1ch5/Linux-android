# LinuxDesk

Android-лаунчер Linux-дистрибутивов «в один тап»: без Termux и без Termux:X11 установки.
Цель: запускать полноценные Linux-десктопы с ускорением GPU (Turnip через KGSL) прямо из приложения.

> **Статус: этап 1, часть A (каркас).** Сейчас приложение умеет: показывать плитки дистрибутивов,
> диагностику устройства, экран логов с кнопкой «Поделиться». Установка образов, `proot`, X11-сервер
> и драйверы Turnip **ещё не подключены**. Сборка APK работает в GitHub Actions.

## Установка (APK)

1. Скачайте `LinuxDesk-<версия>-debug.apk` (или `-release.apk`) из раздела **Releases**.
2. Разрешите установку из этого источника (Настройки → Приложения → Специальный доступ).
3. Для фоновой работы отключите ограничения дочерних процессов:
   Настройки → Для разработчиков (включите режим разработчика, если он выключен) →
   **«Отключить ограничения дочерних процессов»**.
   Приложение проверит это на экране «Диагностика» и покажет подсказку, если опция включена.

## Сборка в CI

Локальная сборка не нужна. Воркфлоу `.github/workflows/build-apk.yml`:

- на каждый push собирает **debug APK** и кладёт его в artifacts запуска;
- на тег `v*` собирает **release APK** и публикует его в Releases.

Release подписывается только если заданы секреты репозитория:

| Секрет | Содержимое |
|---|---|
| `KEYSTORE_B64` | keystore в base64 (`base64 -w0 release.jks`) |
| `KEYSTORE_PASSWORD` | пароль keystore |
| `KEY_ALIAS` | алиас ключа |
| `KEY_PASSWORD` | пароль ключа |

Без `KEYSTORE_B64` release на тег **не публикуется** (чтобы не выпустить APK, подписанный debug-ключом).

## Архитектурные решения

### Почему `jniLibs`, а не `targetSdk 28`

Начиная с Android 10 (targetSdk ≥ 29) приложению запрещено `exec()` файлов из записываемых каталогов
(каталог данных приложения). Есть два пути:

1. **Выбран:** бинарники (`proot`, `loader`) лежат в `app/src/main/jniLibs/<abi>/` как `libproot.so` и
   `libloader.so`. Android устанавливает такие файлы в `nativeLibraryDir`, где `exec` разрешён.
   Включено `useLegacyPackaging = true`, чтобы `.so` лежали на диске как обычные файлы.
   Работает на актуальном `targetSdk` (сейчас 35).
2. Отвергнут: `targetSdk 28`, как у Termux. Это оставляет приложение на устаревшем API и с
   ограничениями, которые новые версии Android ужесточают. Для приложения, которое должно работать на
   Android 16, это плохой долгосрочный выбор.

Rootfs распаковывается в `filesDir` (это данные, а не исполняемый код), запускается через `proot`.

### Почему proot, а не chroot

Без root `chroot` невозможен. `proot` работает в пользовательском пространстве через `ptrace`. Цена —
производительность системных вызовов. Режим chroot с root запланирован как опция на этапе 5.

### Графика (план)

- Встроенный X11-сервер на основе кода Termux:X11 (**GPL-3.0**), поэтому всё приложение GPL-3.0.
- Передача кадров без копирования: AHardwareBuffer / DRI3.
- Turnip (Mesa) собирается **только под KGSL** (`-Dfreedreno-kmds=kgsl`). Обычные пакеты Mesa из
  Debian/Arch на Android не работают.
- OpenGL через Zink поверх Turnip. Если Turnip не инициализировался, приложение падает на llvmpipe и
  пишет понятное сообщение в лог.

### Wayland-десктопы (план)

Вложенная схема: X11 → Weston → композитор (Hyprland / GNOME). Референс: `BlackFireAlex/omarchy-android`.
**Лицензию этого репозитория я не смог проверить**, поэтому из него **ничего не скопировано**; берём
только архитектурные идеи, пока лицензия не подтверждена.

## Лицензии и атрибуция

- Код приложения: **GNU GPL v3.0** (см. `LICENSE`).
- Планируемые заимствования: Termux:X11 (GPL-3.0), Termux proot (GPL-2.0+). Их уведомления будут
  добавлены в `NOTICE` при появлении кода.
- Сторонние образы и драйверы (Mesa, Debian/Arch-пакеты, темы) распространяются под своими лицензиями;
  список будет в `NOTICE` и в `manifest.json` каждого релиза.

## ⚠️ Безопасность

- **proot — не песочница.** Он перенаправляет системные вызовы, но не изолирует процесс от Android. Не
  запускайте в нём недоверенный код, который вы не готовы выполнить от своего имени.
- При прямом доступе к GPU внутри Linux песочница Chromium и подобных приложений может быть отключена
  (`--no-sandbox`), так как пользовательские пространства имён недоступны.
- Файлы в общей папке `/sdcard` доступны гостевой системе. Выдавайте этот доступ осознанно.

## Что тестировать (этап 1, часть A)

На OnePlus 15R (Android 16):

1. Установите debug APK, откройте приложение. Должны показываться 4 плитки дистрибутивов.
2. Нажмите плитку: должно появиться сообщение «установка появится на этапе 2».
3. Откройте **Диагностика**. Проверьте: модель, версия Android, Vulkan (ожидается `1.x.x`),
   статус «Ограничения дочерних процессов» (ожидается «отключены» после шага установки выше).
4. Откройте **Логи** и нажмите **Поделиться**. Пришлите текст лога вместе с описанием того, что увидели.

| 2 | Плитки с превью, настройки, менеджер драйверов, тач-режимы, жесты, звук | — |

## Риски

| Риск | Что делаем |
|---|---|
| Turnip и Adreno 8xx: поддержка свежая, возможны падения драйвера | fallback на llvmpipe с понятным сообщением |
| Phantom process killer убивает сессию в фоне | foreground service + проверка флага и подсказка в UI |
| Лицензия omarchy-android не проверена | код не копируется до подтверждения |
| Сборка X11 из Termux:X11 через NDK сложна и долга | делаем на этапе 1, часть B, отдельными коммитами |
| GNOME без systemd и X11-сессии может не запуститься полноценно | исследование на этапе 4, при неудаче предлагаем компромисс |
| Сетевые лимиты при сборке Gradle (HTTP 429 от Maven) | кеш зависимостей в CI, повтор запуска |
